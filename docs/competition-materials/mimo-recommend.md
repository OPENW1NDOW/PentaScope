### 推荐一：黑灰产情报分析Agent（课题10）

**综合评分：85/100 | 推荐指数：★★★★★**

#### 课题要求拆解

> 抓取 IM、群组、公众号、论坛等多源渠道汇聚的海量情报，利用大模型完成清洗、去重和高危意图分类，抽取黑话、链接、账号、工具等关键实体。分析作弊场景、作恶模式、技术链路，生成总结。禁止通过非法渠道获取数据。

核心交付物：
1. 多源数据采集管道
2. LLM驱动的数据清洗与去重
3. 高危意图分类系统
4. 关键实体抽取（黑话/链接/账号/工具）
5. 作弊场景与技术链路分析
6. 结构化分析报告输出

#### 推荐理由

**1. 竞争压力最小**

这是全部12个课题中预计选择人数最少的方向之一（10-20队）。原因：
- 安全领域对多数参赛者而言门槛较高（需要领域知识）
- 数据获取的合规约束让很多人望而却步
- 课题描述相对"朴素"，不如狼人杀、视频生成等方向吸引眼球

但这些"劝退因素"恰恰是你的机会：技术实现上并不比其他课题更难，且AI Coding能大幅降低安全领域知识的门槛。

**2. 技术路径最清晰**

整条链路是线性管道，每一步都有明确的输入输出：

```
数据源（公开论坛/群组/公众号）
    ↓ 采集
原始数据（文本/链接/图片）
    ↓ LLM清洗+去重
结构化情报
    ↓ 意图分类+实体抽取
标注后的情报数据
    ↓ 场景分析+链路推理
分析结论
    ↓ 可视化
Dashboard + 报告
```

相比"爆款结构迁移引擎"（视频理解→结构抽象→内容重组→包装渲染）这种高度耦合的复杂链路，线性管道的每一层都可以独立开发和测试，大幅降低了集成风险。

**3. AI Coding效率增益最高**

该课题的技术栈与AI辅助编码的契合度极高：

| 模块 | AI Coding优势 |
|------|-------------|
| 数据采集爬虫 | 代码模式固定，AI可快速生成爬虫模板 |
| LLM Prompt工程 | AI最擅长设计和迭代Prompt |
| 数据清洗管道 | 典型的ETL模式，AI生成效率极高 |
| 实体抽取逻辑 | 正则+NLP+LLM组合，AI可快速实现 |
| 前端Dashboard | React Dashboard是AI编码最成熟的场景 |
| 报告生成模块 | 模板化输出，AI可直接生成代码 |

**4. 差异化天然强**

- **赛道稀缺性**：12个课题中唯一的安全方向，评委不会有审美疲劳
- **合规加分**：在"禁止非法渠道"约束下展示合规数据获取能力，体现工程素养
- **技术深度可扩展**：可在基础功能上轻松叠加知识图谱、实时告警、趋势分析等亮点

**5. MVP边界清晰**

3周内的MVP可以精确定义为：
- Week 1：采集3-5个公开数据源 + LLM清洗管道
- Week 2：意图分类 + 实体抽取 + 分析报告生成
- Week 3：前端Dashboard + 系统打磨 + 部署上线

每周末都有可演示的增量交付。

#### 风险与应对

| 风险 | 等级 | 应对策略 |
|------|------|---------|
| 数据获取合规性 | 中 | 聚焦公开可访问的论坛/群组，不触碰隐私数据 |
| 安全领域知识不足 | 低 | LLM可辅助理解黑话和攻击模式，无需深厚安全背景 |
| 数据量不足影响展示 | 中 | 可用LLM生成模拟数据辅助演示，重点展示分析能力 |
| 评委对安全方向不熟 | 低 | 做好可视化和报告输出，降低理解门槛 |

#### 技术栈建议

```
前端：React + TypeScript + Ant Design Pro（快速搭建Dashboard）
后端：Node.js（Express/Fastify）或 Python（FastAPI）
LLM：豆包API / Claude API / GPT API
数据采集：Puppeteer / Playwright + 自定义爬虫
数据存储：SQLite（MVP阶段）→ PostgreSQL
实体抽取：LLM + spaCy / jieba
部署：Vercel（前端）+ Railway/Fly.io（后端）
```

### 推荐二：AI狼人杀（课题6）

**综合评分：75/100 | 推荐指数：★★★★☆**

#### 课题要求拆解

> 构建一个能够自主完成信息不对称博弈的狼人杀 Agent Team 系统。每个 Agent 根据其扮演角色拥有独立的目标、策略与行动空间，在严格信息隔离的约束下进行推理、发言与决策。系统需搭建完整的对局引擎，驱动回合流转与胜负裁决，并输出结构化日志以实现全程可观测。加分项为前端观战 UI。

核心交付物：
1. 狼人杀游戏引擎（回合制状态机）
2. 多角色Agent（狼人/预言家/女巫/村民等）
3. 信息隔离机制
4. Agent推理、发言与决策系统
5. 结构化对局日志
6. 前端观战UI（加分项）

进阶方向（三选一）：
- 通用Agent自演化系统
- 评测+复盘+Leaderboard
- 自进化Agent（对局→分析→优化→再对局）

#### 推荐理由

**1. 规则明确，边界清晰**

狼人杀是规则高度标准化的游戏，不存在"需求不清"的问题。所有角色能力、胜负条件、回合流程都有明确定义。这意味着：
- 开发过程中不会有需求变更
- 测试和验证有明确标准
- MVP范围可以精确控制

**2. 技术深度与趣味性兼具**

- **技术深度**：多Agent协作/对抗、信息不对称推理、博弈策略、状态机引擎
- **趣味性**：狼人杀本身就是大众熟悉的游戏，演示效果直观，评委容易理解

**3. 进阶方向丰富，可拉开差距**

三个进阶方向都极具技术深度：
- **方向②（推荐）**：评测体系 + Leaderboard — 最容易量化展示成果，且复盘归因功能技术含量高
- **方向①**：通用Agent自演化 — 最有想象力，但难度最高
- **方向③**：自进化Agent — 最实用，胜率提升曲线是很好的展示素材

**4. AI Coding效率高**

| 模块 | AI Coding优势 |
|------|-------------|
| 游戏引擎状态机 | 状态机代码模式固定，AI生成效率高 |
| 角色Agent Prompt | Prompt设计是AI最擅长的工作 |
| 前端观战UI | React组件化开发，AI辅助效率极高 |
| 评测/复盘逻辑 | 数据统计+可视化，标准前端开发模式 |

#### 风险与应对

| 风险 | 等级 | 应对策略 |
|------|------|---------|
| 竞争激烈（45-55队） | **高** | 必须在博弈策略深度或UI体验上做出差异化 |
| Agent策略质量参差 | 中 | 设计多套Prompt策略，通过评测体系持续优化 |
| 对局平衡性难调 | 中 | MVP阶段简化角色（6人局），逐步扩展 |
| 演示效果依赖运气 | 低 | 支持回放功能，可选择精彩对局演示 |

#### 差异化策略

在45-55队的竞争中脱颖而出，需要至少做到以下之一：
1. **策略深度**：Agent不是简单套Prompt，而是有推理链、记忆系统、博弈策略库
2. **评测体系**：建立多维度评测（发言质量、投票准确率、存活轮数），产出Leaderboard
3. **UI体验**：观战UI不只是文字日志，而是有动画、角色立绘、实时推理过程可视化
4. **自进化闭环**：实现"对局→分析→优化→再对局"，展示胜率提升曲线

#### 技术栈建议

```
前端：React + TypeScript + Framer Motion（动画）+ Canvas/SVG（对局可视化）
后端：Node.js + TypeScript
LLM：豆包API / Claude API（不同角色可用不同模型对比）
状态管理：XState（游戏状态机）或自研状态机
数据存储：SQLite/PostgreSQL（对局记录+评测数据）
部署：Vercel（前端）+ Railway（后端）
```

### 推荐三：LabelHub数据标注平台（课题12）

**综合评分：78/100 | 推荐指数：★★★★☆**

#### 课题要求拆解

> 完整覆盖数据生产的全生命周期，支持任务负责人配置任务说明，并以拖拽或组件化的方式动态搭建包含多种表单的标注页面；同时实现标注员在线分发与提交、基于自定义评测标准的 AI 自动预审、多角色人工审核流转及多格式数据导出。

核心交付物：
1. 任务管理与配置系统
2. 动态表单搭建引擎（拖拽/组件化）
3. 标注员分发与提交流程
4. AI自动预审Agent
5. 多角色审核工作流
6. 多格式数据导出（JSON/CSV/COCO等）

#### 推荐理由

**1. 需求最明确，完成确定性最高**

数据标注平台是AI行业的刚需工具，市面上已有大量成熟产品（Labelbox、Label Studio等）作为参考。这意味着：
- 产品形态有据可依，不需要从0到1定义
- 技术方案有大量成熟实践可借鉴
- 评委对这类产品的评判标准相对统一

**2. 技术栈成熟，AI Coding效率高**

| 模块 | AI Coding优势 |
|------|-------------|
| CRUD后端 | AI最擅长的代码模式 |
| 动态表单引擎 | 拖拽组件库（如react-dnd）+ 表单渲染，AI可快速实现 |
| 工作流状态机 | 标准状态机模式，AI生成效率极高 |
| AI审核Agent | Prompt工程 + 结果评判，AI辅助设计 |
| 数据导出 | 格式转换逻辑，AI可直接生成 |
| 前端UI | Ant Design Pro等成熟组件库，AI搭建速度极快 |

**3. 差异化空间明确**

在25-35队的竞争中，可以通过以下方式拉开差距：
- **动态表单灵活度**：支持丰富的表单组件（文本/图片/音频/视频/标注框/评分等）
- **AI审核质量**：AI预审不是简单判断对错，而是能给出修改建议和质量评分
- **工作流可视化**：审核流转过程的可视化展示
- **数据导出格式**：支持多种AI训练框架的数据格式

**4. MVP边界清晰**

- Week 1：后端架构 + 任务管理 + 基础动态表单引擎（3-4种组件）
- Week 2：标注提交流程 + AI预审Agent + 审核工作流
- Week 3：前端打磨 + 数据导出 + 端到端测试 + 部署

#### 风险与应对

| 风险 | 等级 | 应对策略 |
|------|------|---------|
| 动态表单引擎复杂度超预期 | 中 | MVP阶段限制组件种类（文本/图片/选择/评分），后续扩展 |
| AI审核准确率不够高 | 中 | 设计置信度阈值，低于阈值自动转人工审核 |
| 工作流状态管理复杂 | 中 | 使用成熟的状态机库，不自研 |
| 与现有开源产品难区分 | 中 | 强调AI审核能力和Agent协作，而非单纯的标注工具 |

#### 差异化策略

1. **AI审核Agent**：不是简单的规则校验，而是LLM驱动的智能审核，能理解标注语义
2. **质量分析仪表盘**：标注员质量评分、标注一致性分析、AI审核准确率追踪
3. **多角色协作**：任务负责人 → 标注员 → AI预审 → 人工审核 → 质检员，完整链路
4. **智能辅助标注**：AI预标注 + 人工修正，提升标注效率

#### 技术栈建议

```
前端：React + TypeScript + Ant Design Pro + react-dnd（拖拽）
后端：Node.js（Express）或 Python（FastAPI）
数据库：PostgreSQL（任务/标注数据）+ Redis（状态缓存）
AI审核：LLM API（豆包/Claude/GPT）
工作流：自研状态机 或 xstate
数据导出：自定义格式转换器
部署：Vercel（前端）+ Railway（后端）
```

## 五、选题后行动建议

无论选择哪个课题，建议按以下节奏推进：

### 第1周：核心链路打通
- 搭建项目骨架（前后端 + 数据库）
- 实现核心功能的最简版本
- 周末产出：可运行的Demo

### 第2周：功能完善 + AI能力集成
- 补充完整业务逻辑
- 集成LLM/AI能力
- 周末产出：功能完整的MVP

### 第3周：打磨 + 部署 + 文档
- UI/UX打磨
- 线上部署
- 撰写项目文档和演示材料
- 最终产出：线上可访问的完整应用

### AI Coding高效使用建议
1. 先用AI生成项目骨架和基础CRUD，快速搭建框架
2. 核心业务逻辑自己把控设计，让AI辅助实现
3. Prompt工程部分充分利用AI迭代优化
4. 前端UI用成熟组件库 + AI辅助，不要从零手写CSS
5. 每完成一个模块立即测试验证，不要积压到最后
