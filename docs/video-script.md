# PentaScope 演示视频脚本

> 目标时长：5-6 分钟
> 录制工具：OBS Studio / Xbox Game Bar (Win+G)
> 分辨率：1920x1080，Chrome 全屏（F11），关书签栏
> 场景：S2 市场进入（有 recommender 推荐环节，最能体现多 Agent 协作）

---

## 段落 1：开场（30s）

**画面**：项目 Logo / 标题页 / 系统架构简图（可用 PPT 全屏）

**旁白/字幕**：
> 大家好，这是 PentaScope——一个 AI 驱动的竞品分析 Agent 协作系统。
>
> 它由 5 个专职 Agent 组成：信息采集、推荐、分析师、报告撰写、质检，
> 通过 LangGraph 编排成一条 DAG 流水线，支持 5 种分析场景，
> 从公开信息采集到 7000-8000 字咨询级竞品报告，全链路自动化。

**动作**：展示架构图 3-5 秒，然后切到浏览器

---

## 段落 2：操作演示——填写表单（1min）

**画面**：Streamlit 前端页面

**旁白/字幕**：
> 我选择「S2 市场进入」场景。这个场景的特点是：用户只需要填写行业名称，
> 系统会先通过推荐 Agent 搜索行业头部玩家，再自动进入采集流程。

**动作**（逐步操作，每步停顿 2-3 秒让观众看清）：
1. 点击场景下拉框，选择「S2 市场进入」
2. 表单切换后，填写：
   - 行业：`AI 代码生成工具`
   - 分析意图：`分析 AI 代码生成工具赛道的竞争格局，评估进入机会`
3. （可选）展示「AI 帮我选场景」按钮的功能
4. 点击「开始分析」按钮

---

## 段落 3：运行过程——展示多 Agent 协作（1-1.5min）

**画面**：前端 spinner + 追溯面板（如果来得及展示节点切换）

**旁白/字幕**：
> 分析已经启动。可以看到系统正在运行——
>
> 第一步，推荐 Agent 从公开搜索引擎搜集这个赛道的头部玩家；
> 第二步，信息采集 Agent 对每个竞品抓取官网、产品文档等公开信息；
> 第三步，分析师 Agent 基于采集数据进行多维度对比分析；
> 第四步，报告撰写 Agent 分 4 个阶段产出完整报告——骨架、场景结构、逐章叙事、代码合成；
> 最后，质检 Agent 对报告进行程序化硬查和 AI 质检，不合格会打回上游重做。

**动作**：
- 展示 spinner 转动（如果 trace 面板可见，展示节点切换日志）
- 如果等待时间太长，此处做剪辑过渡

**剪辑过渡**（5s）：
> （字幕）完整分析需要 12-18 分钟，包含约 10 次大模型调用。以下是分析完成后的结果展示。

---

## 段落 4：报告展示——核心卖点（2-2.5min）

**前提**：报告已预跑完成，用 session_state 恢复展示

**画面**：完整报告页面，从上往下滚动

### 4.1 KPI 仪表盘（20s）

**旁白**：
> 报告顶部是 KPI 仪表盘，5 张卡片分别展示：分析场景、竞品数量、数据来源数、置信度、综合质量分。
> 质量分由质检 Agent 基于溯源完整度、数据可信度、内容质量三维加权计算。

**动作**：鼠标指向每张 KPI 卡片，停顿 1-2 秒

### 4.2 执行摘要（20s）

**旁白**：
> 执行摘要采用五段式结构：背景定位、核心论点、关键发现、战略启示、路径建议。
> 这是 McKinsey/BCG 级别的报告框架。

**动作**：滚动展示 5 段摘要

### 4.3 SWOT 分析（20s）

**旁白**：
> SWOT 四象限分析，每个象限的具体条目都标注了数据来源链接，支持一键跳转到原始网页。

**动作**：指向 SWOT 表格，点击一个 source_refs 链接展示跳转

### 4.4 Plotly 交互图表（30s）

**旁白**：
> 这是 S2 场景的五力分析蜘蛛网图，展示供应商议价力、买方议价力、新进入者威胁、替代品威胁、行业竞争强度五个维度。
> 所有图表都是 Plotly 交互式的，可以缩放、悬停查看详情。

**动作**：鼠标悬停在蜘蛛网图上，展示 tooltip

### 4.5 场景专属内容（30s）

**旁白**：
> S2 场景还包含市场规模估算（TAM/SAM/SOM）、市场进入策略、竞品推荐列表等专属内容。
> 每个数据点都附带置信度评级和数据来源。

**动作**：滚动展示 market_sizing / entry_strategy / competitor_recommendations

---

## 段落 5：亮点特写（1-1.5min）

### 5.1 全链路追溯（30s）

**旁白**：
> 这是系统的可观测性能力。每次分析都会生成一个 trace_id，
> 前端追溯面板可以查看四个阶段的中间产物——采集画像、分析结果、报告草稿、质检反馈。
> 如果质检打回重做，系统会保存每一版快照，支持版本对比。

**动作**：
1. 复制 trace_id 到追溯面板
2. 展示 4 个 tab（profiles / analysis / report / feedback）
3. 展示 meta.json 的 node_trace（节点执行序列）

### 5.2 报告导出（20s）

**旁白**：
> 报告支持 Markdown 和 HTML 两种格式导出。HTML 版本是全内嵌的——
> 字体、CSS、Plotly 图表全部打包在一个文件里，断网也能正常打开。

**动作**：点击「导出 HTML」按钮，展示下载的文件在浏览器中打开

### 5.3 反馈闭环实证（20s）

**旁白**：
> 质检反馈闭环是系统的核心设计。质检 Agent 会检查溯源完整性、数据一致性、Schema 合规性，
> 发现问题按类型打回——回采集补数据、回分析修正、或回撰写重写。
> 最多重试 2 次，超限强制结束。项目经历了 21 轮 Prove-It 修复来验证闭环的有效性。

**动作**：展示 meta.json 中 node_trace 的打回记录（如有）

## 录制前检查清单

- [ ] S2 场景已预跑成功，report 各章节无占位降级
- [ ] quality_score >= 0.65
- [ ] source_refs 有真实 URL（非占位）
- [ ] SWOT / 五力蜘蛛网 / market_sizing 渲染正常
- [ ] Chrome 全屏模式（F11），关书签栏
- [ ] 浏览器字体大小适中（Ctrl+0 重置，或 Ctrl+= 放大 1-2 级）
- [ ] 关闭无关 tab 和通知
- [ ] 麦克风测试（如需语音解说）
- [ ] OBS 录制区域设为 1920x1080

## 剪辑要点

- 等待过程用字幕过渡，不要留空白
- 各段之间加 0.5s 淡入淡出
- 重点内容（KPI、SWOT、图表）用鼠标圈画或放大
- 最终导出 1080p MP4，文件大小控制在 200MB 以内
