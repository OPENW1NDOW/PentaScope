## 二、评估维度说明

每个课题从以下五个维度打分（1-5 星），综合得出"性价比"排名：

| 维度 | 含义 |
|------|------|
| **技术复杂度** | 所需技术栈的广度与深度。星越多越难。 |
| **MVP 明确度** | 最低可交付产品的边界是否清晰。星越多越容易界定。 |
| **竞争烈度** | 预计选题人数。星越多竞争越激烈。 |
| **演示效果** | 答辩演示时的视觉冲击力和互动感。星越多越好。 |
| **外部依赖** | 对第三方 API、平台、数据源的依赖程度。星越多风险越大。 |

性价比 = 综合 MVP 明确度 + 低竞争 + 低依赖 + 高演示效果，扣减过高复杂度带来的风险。

| 维度 | 评分 | 说明 |

| MVP 明确度 | ★★☆☆☆ | "端到端自动生成视频"的边界极其模糊，Prompt 调整/分镜干预/素材混剪都是独立大模块 |

### B4 — AI 狼人杀（★ 第一推荐）

| 维度 | 评分 | 说明 |
|------|------|------|
| 技术复杂度 | ★★★★☆ | 多 Agent 博弈 + 对局引擎 + 信息隔离 + (可选) 观战 UI |
| MVP 明确度 | ★★★★★ | 角色定义 → 对局流转 → LLM 决策 → 日志输出，每一步可独立验证 |
| 竞争烈度 | ★★☆☆☆ | "游戏"题面天然劝退大量参赛者，预计选题数偏低 |
| 演示效果 | ★★★★★ | AI 对战 + 实时观战 UI + 结构化日志，评委可现场互动 |
| 外部依赖 | ★★☆☆☆ | 仅需 LLM API（推理+决策），核心渲染不依赖任何外部服务 |

**优势分析：**

1. **冷门赛道，结构性优势。** 大多数人看到"狼人杀"会下意识归类为"游戏项目"而跳过，转向 AIGC 和电商。实际上它的评判标准完全在于系统设计能力——多角色的信息隔离、推理链的 prompt 工程、回合制状态机——这些与字节面试考察的核心能力高度一致。
2. **MVP 路径极度清晰。** 最小闭环：角色定义 → 对局引擎（硬编码回合流转）→ LLM 推理接口 → 结构化日志输出。每一步都有明确的验收标准（"能不能跑通一局"），不存在需求模糊的问题。
3. **三个进阶方向自由控制深度。**
   - 方向一（通用 Agent→狼人杀 Agent）：自演化系统
   - 方向二（评测+复盘）：多维量化评测 + Leaderboard
   - 方向三（自进化 Agent）：对局→分析→优化→再对局循环
   
   三个方向互不阻塞，选一个做深即可在决赛轮形成差异化。
4. **外部依赖最低。** 不像 AIGC 需要火山引擎视频 API、RAG 需要向量数据库、竞拍需要 WebSocket 基础设施。核心引擎是"LLM 推理 + 规则逻辑"，完全在你控制范围内。
5. **字节 Agent 战略方向。** 字节内部在大力推 Agent 协作方向，多 Agent 博弈是其中最硬核的子领域。出题人大概率偏好这个赛道的深度方案。
6. **演示的互动性极强。** 评委可以在观战 UI 上实时看到各 AI 角色的推理过程、投票决策和博弈结果，形成"AI 直播"的观感。

**风险与应对：**

- **Prompt 工程深度：** 博弈逻辑（谎话检测、角色扮演一致性、逻辑推理）的 prompt 设计是核心竞争力。建议提前设计 prompt 模板体系，使用 system prompt + few-shot + chain-of-thought 三层结构。
- **对局平衡性：** 如果 AI 狼人胜率过高或过低，需要引入难度调节参数。

**建议技术栈：** Python（后端+Agent框架）+ React（观战UI）+ LLM API（OpenAI-compatible）

### C1 — 电商直播竞拍（★ 第三推荐）

| 维度 | 评分 | 说明 |
|------|------|------|
| 技术复杂度 | ★★★★☆ | React + WebSocket + Node.js/Go + 状态一致性 + 高并发 |
| MVP 明确度 | ★★★★☆ | 商品上架→规则设定→实时出价→排名计算→成交，链路天然完整 |
| 竞争烈度 | ★★☆☆☆ | 电商赛道大多数人流向 AIGC 和 RAG 导购，竞拍因"WebSocket+高并发"被回避 |
| 演示效果 | ★★★★★ | 实时出价动画 + 倒计时 + 落锤特效，极有冲击力 |
| 外部依赖 | ★★★☆☆ | WebSocket 库和消息队列成熟，无不可控的外部 API |

**优势分析：**

1. **技术栈友好，套件成熟。** WebSocket（Socket.IO / ws）+ 状态机 + 前端实时渲染，业界有大量成熟方案，不存在探索性技术风险。
2. **演示效果炸裂。** 实时出价跳动、倒计时压力、落锤成交动画——答辩时打开多个浏览器窗口模拟竞拍者，效果直接拉满。
3. **"毫秒级实时通信 + 状态一致性"是字节面试硬核考点。** 评委看到你在这个方向上的深度设计（乐观锁/悲观锁策略、消息有序性保证、断线重连状态恢复）会产生强烈技术认同。
4. **AI 加分项有弹性。** 题目明确鼓励探索 AI 在动态定价和气氛营造中的应用——做了是清晰加分，不做也不影响系统完整度。建议至少做 AI 起拍价建议或 AI 拍卖师解说。
5. **Go 选型有额外优势。** 如果后端选 Go 而非 Node.js，在字节技术栈匹配度上额外加分。

**风险与应对：**

- **高并发测试：** 需要准备 WebSocket 压测 demo（可用 k6 / Artillery），证明系统的并发能力。
- **竞拍状态机设计：** 需要仔细处理边界情况（同一毫秒的出价排序、网络延迟导致的超时出价）。

**建议技术栈：** Go / Node.js（后端）+ React（前端）+ WebSocket（Socket.IO）+ Redis（出价队列/排名）

### E1 — 黑灰产情报分析 Agent（★ 第二推荐）

| 维度 | 评分 | 说明 |
|------|------|------|
| 技术复杂度 | ★★★☆☆ | Python + LLM + NER + 前端 Dashboard |
| MVP 明确度 | ★★★★☆ | 采集→清洗→分类→抽取→总结，天然 DAG 流水线 |
| 竞争烈度 | ★☆☆☆☆ | AI 安全是"冷门之王"，预计选题数垫底 |
| 演示效果 | ★★★☆☆ | 情报 Dashboard + 实体关系图 + 威胁报告，专业感强但缺互动 |
| 外部依赖 | ★★☆☆☆ | LLM API 即可，数据可用公开安全情报源或模拟数据 |

**优势分析：**

1. **竞争烈度极低。** AI 安全属于小众赛道，绝大多数参赛者不会碰。如果各赛道晋级名额独立分配，冷门赛道天然有更高的晋级概率——类似于高考的"冷门专业分数线更低"。
2. **题面天然为 Agent 流水线设计。** 数据采集 Agent → 清洗去重 Agent → 意图分类 Agent → 实体抽取 Agent → 总结报告 Agent，每一步就是一个独立的 Agent 节点，天然形成 DAG 工作流，不需要强行拆解模块。
3. **技术复杂度在所有课题中最低。** 不需要高并发、不需要实时通信、不需要视频/图像处理、不需要移动端开发。全链路基于 LLM API + 规则引擎即可完成，精力可以全部投入到 Agent 调度逻辑和 prompt 优化上。
4. **数据问题有弹性空间。** 题目明确说"禁止通过非法渠道获取数据"，反向推理——公开情报源（安全社区、威胁情报平台 RSS、安全公众号）是合规的。且安全情报分析本身不要求"真实数据"，用模拟的黑灰产情报数据（自己构造的 IM 聊天记录、公告文本）做 demo 完全合理。
5. **字节安全团队的真实需求信号。** 这道题出现在比赛课题里，说明字节内部对 AI 驱动的自动化安全情报有真实业务需求。方案如果能贴合字节安全团队的痛点，会有额外加分。
6. **Demo 演示的信息密度高。** 一个情报 Dashboard 展示：原始数据 → 去重后的关键情报 → 实体关系图谱 → 自动化分析报告，信息密度和专业感远超简单的 CRUD 系统。

**风险与应对：**

- **实体抽取质量是核心竞争力。** 黑话识别（如"料"=信用卡数据、"盾"=安全防护）需要领域知识，建议提前搜集常见黑灰产术语构建 few-shot 样本库。
- **演示缺乏互动性。** 这是报告输出型系统的通病。弥补方案：在前端加入"情报溯源"交互——点击任意分析结论，能下钻到原始数据源和中间推理过程，把"可观测性"变成演示亮点。

**建议技术栈：** Python（FastAPI）+ LangChain（Agent 编排）+ LLM API + React（Dashboard）+ ECharts/D3（知识图谱可视化）

### F1 — "超级个体"全栈交付

| 维度 | 评分 | 说明 |
|------|------|------|
| 技术复杂度 | ★★★★★ | Agent 编排 + code-gen + AST 定位 + 自动化测试 + CI/CD + 知识回写 |
| MVP 明确度 | ★☆☆☆☆ | "需求澄清→方案拆解→模块定位→代码生成→测试→部署"每一步都是独立课题 |
| 竞争烈度 | ★★★★★ | "端到端 AI 编程"是本赛最高热度的理念，预计选题数极高 |
| 演示效果 | ★★★☆☆ | 对话式编程界面，演示效果依赖代码生成质量（不可控） |
| 外部依赖 | ★★★★☆ | 强烈依赖 LLM 的 code generation 能力，质量波动大 |

**结论：❌ 强烈不推荐。** 题面是所有课题中最大的。"需求澄清→方案拆解→代码生成→自动化测试→部署" 中任何一个环节做深都是一个完整项目。3 周单人不可能在每个环节都做到及格线，最终必然每个环节都是"浅尝辄止"，得分平庸。且"AI 编程"概念太性感，预计大量强队涌入，竞争惨烈。

### F2 — LabelHub 数据标注平台

| 维度 | 评分 | 说明 |

| 外部依赖 | ★★★☆☆ | 中等 |

**结论：⚠️ 备选。** 动态表单引擎和工作流引擎是两个硬骨头。如果没有现成方案或深厚的前端架构经验，3 周很容易陷入表单引擎的泥潭而忽略其他模块。

## 五、最终推荐方案

### 第一志愿：B4 — AI 狼人杀

> **冷门赛道 × 多 Agent 博弈热点 × MVP 极度明确 × 自由进阶空间**

- 匹配 Python 全栈选手（Agent 框架 + React 观战 UI）
- 核心投入：博弈 prompt 工程 + 对局引擎状态机
- 进阶选择：自进化 Agent 循环（方向三），做 50 局对局的胜率收敛曲线，论文感强，答辩有数据说服力

### 第二志愿：E1 — 黑灰产情报分析 Agent

> **最冷门赛道 × 天然 Agent DAG × 外部依赖极少 × 字节安全团队需求**

- 匹配 Python 全栈选手（FastAPI + LangChain + React Dashboard）
- 核心投入：NER prompt 工程 + 黑话词典 + 知识图谱可视化
- 亮点设计：可溯源情报分析（"每条结论可点击下钻到原始数据源"）

### 第三志愿：C1 — 电商直播竞拍

> **技术成熟 × 演示效果炸裂 × 评委偏好明显 × 竞争偏低**

- 匹配 TypeScript/Go 全栈选手（WebSocket + 状态机 + React）
- 核心投入：竞拍状态机 + 实时排名算法 + 高并发压测
- 加分设计：AI 拍卖师（动态定价建议 + 实时解说）
