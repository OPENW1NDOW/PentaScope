# 字节跳动 AI 全栈挑战赛课题推荐报告

## 一、分析前提

本报告基于 `programs.md` 中给出的全部可选课题进行评估，核心目标不是单纯判断“哪个题目最酷”，而是站在 **3 周时间、个人独立开发、需要完成端到端交付与线上展示** 的现实约束下，寻找 **最合适、性价比最高、最有机会做出完整作品** 的方向。

本次评估重点考虑以下几个维度：

- **技术实现复杂度**：前后端、模型、数据、工作流、部署链路是否过重。
- **个人可控性**：是否能在 3 周内由 1 人稳定完成 MVP，并留出打磨时间。
- **评委感知价值**：是否容易讲清楚业务意义、AI 价值和工程亮点。
- **交付完整度**：是否容易做出“能跑、能演示、能上线”的完整系统。
- **赛道拥挤度**：预计选择该课题的队伍多不多，是否容易出现同质化竞争。
- **性价比**：投入产出比是否足够高，是否值得在有限时间内投入。

---

## 二、推荐结论

结合以上维度，我最推荐的 3 个课题是：

### 1. AI 驱动的竞品分析 Agent 协作系统

这是综合得分最高的题目，原因在于它同时具备：

- 强 AI 属性：天然适合做多 Agent、RAG、报告生成、质检闭环。
- 强业务价值：竞品分析是非常典型的企业真实需求，评委容易理解。
- 强工程闭环：采集、分析、撰写、审查、引用溯源、结果展示，链路完整。
- 风险相对可控：即使部分数据抓取不稳定，也可以通过搜索、网页解析、文档导入等方式降级实现。
- 易于讲故事：从“传统竞品分析费时费力”切入，到“多 Agent 协作自动生成可溯源报告”，叙事非常顺。

### 2. 黑灰产情报分析Agent

这是一个 **热度较低但很容易做出专业感和差异化** 的课题，尤其适合想避开热门赛道、提高突围概率的参赛者。

- 任务边界清晰：采集、清洗、分类、实体抽取、情报关联、报告生成，模块清楚。
- AI 价值明确：意图分类、实体识别、风险归因、总结输出都可以体现模型能力。
- 展示专业感强：时间线、关系图谱、风险告警、来源证据都很适合做成“像真实系统”的效果。
- 同质化概率低：相比竞品分析、AgentHub、视频生成等热门方向，预计选择人数会少很多。

### 3. LabelHub 数据标注平台

这是一个 **最容易做出高完成度正式产品形态** 的课题，很适合想在 3 周内确保交付质量的人。

- 全栈特征明显：前端复杂交互、后端流程、权限角色、审核流、导出能力都很能体现工程实力。
- AI 使用场景自然：可以把 AI 用在预标注、自动预审、质量检测、审核建议等环节。
- 产品闭环完整：任务配置、标注执行、AI 预审、人工审核、结果导出，路径清楚。
- 可控性较高：相比视频、多模态移动端、复杂实时协作平台，对外部数据与复杂模型效果依赖更低。

---

## 三、为什么推荐这 3 个题目

### 1. 它们都能在 3 周内形成完整 MVP

一个比赛项目真正的难点，不只是把几个功能点做出来，而是要做到：

- 有明确输入和输出；
- 有用户使用路径；
- 有核心 AI 能力；
- 有工程闭环；
- 有可视化演示；
- 最好还能上线。

推荐的这 3 个课题都满足这个条件：

- `竞品分析 Agent`：输入竞品和分析目标，输出结构化竞品报告与证据链。
- `黑灰产情报分析Agent`：输入情报数据，输出风险分类、实体关联和总结报告。
- `LabelHub`：输入任务和数据，输出审核通过后的结构化标注结果。

这类项目的共同特点是：**链路长但不失控，功能多但都能压缩成 MVP**。

### 2. 它们更容易体现“AI Coding + 全栈工程 + 真实业务”

比赛强调的是围绕真实业务做端到端交付，而不是单纯做一个模型演示或者一个前端页面。

这 3 个题目最适合体现以下能力：

- 使用 AI 辅助完成需求拆解与系统设计；
- 用全栈技术搭出完整的前后端系统；
- 在核心链路里真正用到大模型能力；
- 把 AI 能力产品化，而不是只停留在接口调用；
- 做出对业务有价值的结果。

### 3. 它们的风险比视频类、移动端类、平台基础设施类更低

某些题目虽然看起来更炫，但对个人 3 周项目并不友好，例如：

- 视频生成类题目依赖多模态能力、素材处理、FFmpeg、质量调优，链路长且效果不稳定。
- 原生移动端导购类题目需要同时处理客户端、流式交互、RAG、多模态解析，负担太重。
- 多 Agent 平台类题目偏基础设施，集成复杂度高，很容易把时间耗在底层框架而不是结果展示上。

相比之下，这 3 个推荐方向更容易做到：

- 架构不失控；
- 功能可裁剪；
- 演示可闭环；
- 风险可降级；
- 成果可解释。

## 四、Top 3 详细分析

## 1. AI 驱动的竞品分析 Agent 协作系统

### 推荐指数

- **综合推荐度**：5/5
- **实现难度**：3.5/5
- **展示效果**：4.5/5
- **预估热门程度**：高
- **预估选择队伍数**：约 8-14 队 / 每 100 队

### 推荐理由

这是一个非常适合比赛的“标准强题”。

它最有优势的地方在于：**业务合理、AI 合理、系统合理、答辩也合理**。

你可以很自然地把系统拆成多个 Agent：

- 采集 Agent：负责搜索公开信息、网页抓取、文档解析。
- 分析 Agent：负责信息结构化、竞品维度提取、优劣势归纳。
- 撰写 Agent：负责将分析结果组织成报告。
- 质检 Agent：负责检查引用充分性、结论一致性、信息缺失。
- Orchestrator：负责任务流转、状态管理、依赖编排。

这个架构既符合题目要求，又非常利于展示。

### 优点

- **天然适合多 Agent**：不是强行套 Agent 概念，而是任务本身就适合角色拆分。
- **可溯源能力容易做亮点**：每条结论挂上引用来源，会显得非常专业。
- **MVP 边界清晰**：只做网页信息采集 + 报告生成 + 质检闭环就足够成型。
- **业务故事强**：企业确实存在竞品调研效率低的问题，评委很容易共鸣。
- **可演示性强**：输入竞品名称后，自动生成对比报告，展示感很好。
- **扩展空间大**：后续可加入 DAG 可视化、追问问答、行业模板、评分体系等高级功能。

### 缺点

- **赛道会比较热门**：容易遇到其他队伍也做类似方向。
- **数据采集质量影响较大**：搜索和网页解析的稳定性需要考虑。
- **如果只做“问答 + 报告”会显得普通**：必须突出 Agent 协作、溯源、质检等差异化能力。

### 适合什么样的人

- 擅长 Web 全栈开发；
- 对 Agent workflow、RAG、报告生成比较熟悉；
- 希望做一个“既能讲 AI，又能讲工程，又能讲业务”的项目；
- 希望答辩时逻辑清晰、容易获得认可。

### 建议的亮点方向

- 报告中的每个结论都可点击查看原始证据来源。
- 用 DAG 或任务时间线展示多个 Agent 的协作过程。
- 增加“交叉审查”机制，让质检 Agent 给出修改建议。
- 支持多轮追问，例如“进一步分析商业模式差异”。

### 最大风险

最大的风险不是技术做不出来，而是做出来后和其他队伍太像。因此一定要把亮点放在：

- 可溯源报告；
- Agent 间协作与审查；
- 结构化 Schema；
- 过程可观测性。

## 2. 黑灰产情报分析Agent

### 推荐指数

- **综合推荐度**：4.8/5
- **实现难度**：3-3.5/5
- **展示效果**：4/5
- **预估热门程度**：低
- **预估选择队伍数**：约 2-5 队 / 每 100 队

### 推荐理由

这是一个非常值得重视的“低热度高回报”选题。

它的最大优势在于：**题目听起来专业，任务链路明确，AI 参与度高，而且同质化少**。

你可以把整个系统设计成：

- 数据采集模块：导入公开论坛、群组、公众号、网页等情报内容。
- 清洗去重模块：去除广告、重复文本、低质量内容。
- 风险识别模块：对高危意图进行分类。
- 实体抽取模块：识别黑话、链接、账号、工具、目标对象等实体。
- 关联分析模块：构建事件、人物、工具、渠道之间的关系。
- 总结报告模块：输出结构化研判结果。

### 优点

- **赛道冷门，容易差异化**：做得中上就容易显得特别。
- **AI 任务非常聚焦**：分类、抽取、归因、总结，全都是模型擅长的事。
- **系统专业感很强**：哪怕 UI 不复杂，只要有图谱、告警、来源、时间线就很像“真系统”。
- **容易形成闭环**：输入情报，输出分析结果，价值清晰。
- **容易做评测**：可以对分类准确性、实体抽取质量、摘要质量做定量评估。

### 缺点

- **数据合规要求高**：必须非常明确只使用合法公开数据或模拟数据。
- **领域知识门槛稍高**：如果不了解黑灰产语境，Prompt 和标签体系需要花时间打磨。
- **部分评委可能不如电商/Agent 平台题目直观**：需要在答辩里把业务价值讲清楚。

### 适合什么样的人

- 希望避开拥挤热门赛道；
- 更擅长信息处理、文本分析、知识抽取类任务；
- 能接受稍微偏“行业系统”而不是消费级产品的展示风格；
- 想靠专业度和差异化取胜。

### 建议的亮点方向

- 输出实体关系图谱，展示账号、工具、话术、目标对象之间的关系。
- 增加风险事件时间线，突出“情报演化过程”。
- 做一个可解释面板，显示风险分类依据。
- 加入案件/模式归因总结，体现比普通分类器更强的分析能力。

### 最大风险

主要风险在于数据来源和领域定义。如果你没有稳定的公开数据源，建议从一开始就采用：

- 公开网页内容；
- 自建模拟样本；
- 结构化案例集合；
- 小规模人工标注数据集。

这样可以降低合规和数据不稳定风险。

## 3. LabelHub 数据标注平台

### 推荐指数

- **综合推荐度**：4.6/5
- **实现难度**：4/5
- **展示效果**：4/5
- **预估热门程度**：中
- **预估选择队伍数**：约 4-7 队 / 每 100 队

### 推荐理由

如果你的目标是：**在 3 周内做出一个最像正式产品、交付完成度最高的系统**，那么 LabelHub 是非常稳的选择。

这个题目并不依赖非常前沿的模型效果，而是更考验真正的全栈工程能力，这反而适合个人开发者用 AI Coding 快速推进。

一个比较合理的 MVP 可以是：

- 任务负责人创建标注任务；
- 通过配置表单组件生成标注页面；
- 标注员领取任务并提交结果；
- AI 审核 Agent 自动进行预审；
- 审核员查看建议并做最终判断；
- 系统导出结构化标注结果。

### 优点

- **最容易做出完整产品感**：权限、状态流转、页面交互、后台管理都很好落地。
- **全栈能力体现充分**：前后端、工作流、数据库、导出、审核逻辑都很实在。
- **AI 部分容易做得自然**：AI 预标注、质量检查、审核建议都能很好地嵌入流程。
- **交付稳定性强**：不太依赖视频、多模态、移动端或复杂外部数据源。
- **适合做上线演示**：后台系统类产品很容易部署并现场操作展示。

### 缺点

- **视觉冲击力不如视频/Agent 对话类项目**：第一眼不一定最吸睛。
- **如果 AI 部分做得太弱，会显得偏传统后台系统**。
- **动态表单和审核流如果做太大，容易失控**：必须一开始就压缩 MVP 范围。

### 适合什么样的人

- 擅长 React、Node.js、数据库建模和后台系统设计；
- 希望项目稳定可交付，不想把时间过多花在模型调参上；
- 更重视完成度、系统性和产品感；
- 想做一个上线后依旧能继续扩展的工程型作品。

### 建议的亮点方向

- 配置式搭建标注页面，而不是写死字段。
- AI 审核给出“问题原因”和“修改建议”，而不是只打分。
- 增加审核一致性分析或低质量标注拦截。
- 支持导出 JSON、CSV 等多种结构化格式。

### 最大风险

最大风险不是做不出来，而是做成一个“普通管理后台”。因此必须强化：

- AI 预审能力；
- 审核解释性；
- 复杂状态流转；
- 动态任务配置能力。

## 五、其他课题为什么没有进入前三

### 1. 电商 AIGC 带货视频生成系统

**优点**

- 题目吸睛，演示效果强。
- 很符合当下 AIGC 热点。
- 如果做得好，评委印象会很深。

**缺点**

- 视频生成链路极长，涉及脚本、分镜、素材、渲染、混剪、分析等多个环节。
- 很依赖外部模型能力和调参效果。
- 3 周单人很容易只完成一个半成品。
- 预计参赛人数较多，竞争会比较激烈。

**结论**

除非你本身就有视频生成、FFmpeg、多模态处理经验，否则不建议优先选择。

### 2. 爆款结构迁移引擎

**优点**

- 创意性很强，概念很高级。
- 如果结构迁移效果好，会非常有说服力。

**缺点**

- 真正难点不在“做出来”，而在“迁移得是否像样”。
- 评估标准偏主观，容易陷入“看起来有点像，但不够 convincing”。
- 涉及样例理解、结构抽取、重组生成、包装输出，链路较长。

**结论**

适合对视频理解和创作结构化表达很有经验的人，但对一般个人参赛者来说风险偏高。

### 3. 基于 RAG 的多模态电商智能导购 Agent

**优点**

- 业务场景真实，商业价值强。
- 多模态 + RAG + 原生客户端，技术亮点很足。

**缺点**

- 原生移动端开发本身就很耗时。
- 还要同时处理知识库、多轮对话、流式交互、图片理解、卡片渲染、评测闭环。
- 对个人 3 周项目来说过重。

**结论**

好题，但不适合把成功率放在第一位的参赛者。

### 4. AgentHub - 多 Agent 协作平台

**优点**

- 题目很“潮”，容易体现 Agent 协作理念。
- IM 形态有较强产品感。

**缺点**

- 本质上是平台型基础设施项目，功能面太广。
- 适配器层、会话管理、协同协议、Diff、部署、预览等都不轻。
- 很容易只做出一个“会聊天的壳”。

**结论**

不建议在 3 周单人赛里作为首选。

### 5. AI 狼人杀

**优点**

- 演示趣味性强，观战体验好。
- 多 Agent 推理和博弈空间很大。

**缺点**

- 商业和业务落地价值不如前几个题目直观。
- 答辩时如果评委更看重真实业务，会稍显吃亏。
- 策略深度如果不够，容易变成“会说话的脚本游戏”。

**结论**

适合强调多智能体推理研究感的作品，不是最稳妥的比赛选择。

### 6. 抖音电商直播竞拍全栈系统

**优点**

- 系统感强，实时互动演示效果很好。
- WebSocket、状态同步、竞拍规则都很适合做工程亮点。
- 成品形态容易“像上线产品”。

**缺点**

- AI 成分天然没有 Agent / 情报分析 / 导购类题目那么强。
- 实时系统要做好状态一致性和异常处理，需要不少工程功夫。

**结论**

这是一个非常不错的备选题，尤其适合偏全栈工程、实时系统方向的人。如果你不想做文本智能系统，它是很好的替补前三。

### 7. 基于短剧内容理解的即时互动激发

**优点**

- 有差异化，偏内容理解，方向比较新。
- 如果高光识别做得好，会很有趣。

**缺点**

- 核心难点在于“高光点识别质量”。
- 数据和评价标准不太好建立。
- 客户端互动设计也需要时间打磨。

**结论**

可做，但结果不够稳。

### 8. 智能识物比价购物 AI APP 助手

**优点**

- 直观、容易理解。
- 拍照识物的演示效果不错。

**缺点**

- 数据源是最大问题，比价、商品聚合、价格趋势都需要较强数据支撑。
- 原生端开发 + 商品检索 + 多轮筛选整体工作量很大。
- 禁用端侧 AI SDK 后实现复杂度进一步上升。

**结论**

看上去简单，实际坑很多，不推荐作为高优先级选择。

### 9. 实现一个可以端到端交付全栈项目的“超级个体”

**优点**

- 非常符合 AI Coding 比赛主题。
- 如果做得出来，会非常有话题性。

**缺点**

- 题目范围过大，几乎是平台级系统。
- 涵盖需求澄清、任务拆解、模块定位、代码生成、测试、部署、知识回写等全链路。
- 3 周单人完成难度极高。

**结论**

不建议碰，这是典型的“听起来很强、做起来极容易失控”的题目。

### 第一推荐：AI 驱动的竞品分析 Agent 协作系统

### 第三推荐：LabelHub 数据标注平台

最容易做出高完成度正式产品，适合强调交付质量和工程稳定性的人。
